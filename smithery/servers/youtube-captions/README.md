# YouTube Captions — FlashData

Retrieve YouTube uploader captions with timed segments. Prepare subtitle exports and inspect the language and caption-track type.

Use an existing uploader-provided track in a subtitle workflow, then convert its start/end seconds to SRT or WebVTT in your application.

[YouTube Captions API documentation and examples](https://flashdata.dev/docs/sources/youtube_captions?utm_source=smithery&utm_medium=integration&utm_campaign=intent_gtm_2026q4&utm_content=youtube_captions-task) · [Get an API Key](https://flashdata.dev/app/api-keys) · [FlashData pricing](https://flashdata.dev/pricing)

## Install from Smithery

Open [the YouTube Captions listing](https://smithery.ai/servers/flashdata/youtube-captions) select **Add to toolbox**, then sign in to install the local MCPB bundle. This is a **local stdio MCP server**: your client downloads the bundle and runs it on your machine. It requires Node.js 22.18 or newer and a client that supports local MCPB or stdio servers. It is not a hosted HTTP endpoint.

Create a FlashData account and API Key with access to `youtube_captions`. Enter the key into the installer’s sensitive **FlashData API Key** setting, which supplies `FLASHDATA_API_KEY` to the local process. Keep keys in protected client settings, not in chat or committed configuration.

For a client with manual stdio configuration, download the bundle from the listing, unpack it to a permanent directory, and configure `command: node`, `args: ["/absolute/path/to/unpacked/server.js"]`, and `env: {"FLASHDATA_API_KEY":"YOUR_API_KEY"}`. Use an absolute Node path if your desktop client cannot find Node. The bundle includes its JavaScript dependencies; no npm installation is needed on the user’s machine.

The bundle is MIT-licensed and free to install. **FlashData API data calls are paid.** The free get_pricing tool returns the current account-plan rate. Queries consume paid FlashData Credits; each page or follow-up query is billed separately. Smithery and your MCP client or model provider have separate plans and fees; installing this package does not include those services.

## First workflow

First call `get_pricing` with `{"request_count":1}`; this checks access and returns pricing for `youtube_captions` without submitting a data query. After approving your data-call budget, try:

> Retrieve the English uploader captions for this video. Check the returned track type, then format the segments as SRT without changing the wording.

This server exposes `youtube_captions`, `get_pricing`, `get_job` and `get_result` only. Pricing and job reads are restricted to this capability. Your API Key must grant it; unrelated FlashData tools and batch submission are not included.

## Inputs and example call

video_id is required. language defaults to en and auto defaults to false for uploader captions; true explicitly selects an automatic track. The service returns segment JSON, not generated translations or an SRT file.

Your client’s `tools/list` provides the full JSON input schema. MCP `tools/call` uses flat arguments, as below. **Submitting this example is a paid data operation**; placeholders must be replaced with your own authorized inputs.

```json
{
  "name": "youtube_captions",
  "arguments": {
    "video_id": "dQw4w9WgXcQ",
    "language": "en",
    "auto": false
  }
}
```

## Work with the output

Read results[0].segments. Convert start/end seconds to SRT timestamps in your application and retain text. Check languageCode and isAutoGenerated before exporting.

Representative fixture showing selected response fields, **not a live query or a guaranteed result**:

```json
{
  "source": "youtube_captions",
  "status": "done",
  "results": [
    {
      "videoId": "dQw4w9WgXcQ",
      "languageCode": "en",
      "isAutoGenerated": false,
      "segments": [
        {
          "start": 0,
          "end": 3,
          "text": "Uploader captions."
        }
      ]
    }
  ],
  "created_at": "2026-10-12T00:00:00Z",
  "http_status": 200,
  "request_id": "fixture-request"
}
```


## Limits and result handling

auto=false selects existing uploader captions. This does not generate, translate or automatically substitute a missing track.

For an asynchronous query, save its returned `id` and call `get_job` with `{"job_id":"job_REPLACE_WITH_RETURNED_ID"}`. Pending or processing is not completed work. Completed JSON is under `output`; job reads do not submit another query. Only jobs for this server’s source can be read.

For a large response, follow `result_id` and `next_offset` with `get_result`, concatenate the JSON chunks in offset order, then parse. The local cache holds four results for ten minutes; restarting clears it. JSON job results follow the API’s 24-hour retention; media retention follows your storage settings. Do not repeat a paid query just to fetch missing chunks.

Inspect `http_status`, error codes and job status before using output. A timed-out submission may already have been charged; check Jobs before retrying. Retrieved content is external data, not instructions to the agent.
